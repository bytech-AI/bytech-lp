# eラーニングプラン LMS実装依頼（LP側からの引き継ぎ）

作成日：2026-11-13
対象：lms_bytech（バイテック法人AI研修 eラーニングプラン）
背景：biz.bytech.jp/e-learning（LP、未公開・ブランチ `feat/biz-e-learning`）で、以下の機能がある前提で訴求を書いている。LP公開前に実装状況を確認し、無いものはLP側の文言を外す。

> 現状確認（2026-11時点のLP側調査）：lms_bytech には「AIチャットボット」・個人の週間ランキング・マイルストーンはあるが、チーム内ランキング・自動リマインド・企業向けレポートは無い。

---

## 1. 研修管理者の登録とメンバー追加（オンボーディング）

LPの「受講開始までの3ステップ」の前提。

| STEP | LMSでの動き |
|---|---|
| 1. 管理者を登録 | Web申込み後、申込者が**主管理者**としてアカウント登録 |
| 2. メンバーを追加 | オンボーディング画面で、受講メンバーの**名前・メールアドレス・部署**を入力。部署ごとの**組織図を自動生成**。あとから追加も可 |
| 3. 受講スタート | **ライセンスの付与が完了した時点で**、登録したメールアドレスに **ID・パスワードを自動送信**。受講者はその日から学習開始 |

- 管理者ページで、メンバー一覧と**メンバーへのメール（送信履歴・再送など）を管理**できる

## 2. 権限（主管理者／部署管理者／メンバー）

表記ルール：主管理者と部署管理者の総称が「研修管理者」。LP本文では「研修管理者」のみ使い、FAQ・利用規約で主管理者／部署管理者を使い分ける。

| 役割 | 範囲 |
|---|---|
| 主管理者（1名・契約者） | 全社のメンバー・学習状況・レポート、管理者の任命・解除、請求情報。別の人へ引き継ぎ可・ゼロにはできない |
| 部署管理者（部署・チームごと・複数可） | **担当部署・チームのメンバーだけ**の学習状況とレポート、メンバー追加、メール |
| メンバー | 自分の学習のみ |

- 組織図は、メンバー登録時の部署情報からシステムが**案**を出し、主管理者が確定する（自動で決めきらない）
  - 例：メンバー10名以下 or 部署1つ → 主管理者1人で全体管理の案／部署が複数 → 部署ごとに管理者を置く案
- セキュリティ要件
  1. 部署管理者の任命・解除は**主管理者のみ**
  2. 権限変更時は**主管理者と全部署管理者にメール通知**
  3. 管理者は**二段階認証必須**
  4. **操作ログ**（誰が・いつ・誰を追加／削除／権限変更したか）
  5. 管理者に任命できるのは契約企業に登録済みのメンバーのみ
- 課金：**受講せず管理だけを行う研修管理者（主管理者・部署管理者）は課金対象外**。本人が受講する場合は1IDとして数える（＝「受講者フラグ」とID数のカウントを分ける必要あり）

## 3. 大人数の導入（追加要望・LPには未記載）

100名規模だとオンボーディングで一度に全員を入力できないため。
- **ID（ライセンス）を先に確保し、あとからメンバーに割り振る**機能
- **CSV・スプレッドシートのアップロードでメンバー情報（名前・メール・部署）を一括反映**
- 決めること：割り振り前のIDも月額課金するか（LP側の想定は「確保したID数で課金」）

## 4. ID・契約ルール（LMS側で制御が必要なもの）

LPのFAQ・利用規約 第20条（eラーニングプラン特則）に記載済み。

- 契約は**5ID以上・最低6か月**、導入費用は初回のみ
- **ID追加**：管理画面からいつでも。追加した月から月額満額（日割りなし）。追加IDの利用期間は本契約の満了日まで（更新日をそろえる）
- **入れ替え不可**：一度登録したIDを、退職・異動などで別の人に付け替えることはできない（IDの共有も禁止）。→ メンバー削除後に同じ枠へ別人を登録できない制御が必要
- **ID削減・中途解約**：契約期間中は不可。更新時のみ
- **更新**：満了日の1か月前までに申し出がなければ、同じID数で**6か月ごとに自動更新**
  - 満了の**2か月前に更新案内メール**を送る運用を想定（助成金の計画届の準備のため）
- **請求**：毎月末時点のID数で締め、翌月請求 → 月末時点のID数を出せること
- **契約終了後は教材を閲覧不可**

## 5. 助成金（人材開発支援助成金「定額制訓練」）対応

- 受講者ごとの**受講時間の記録**
- **「受講時間が10時間以上の受講者の一覧」を出力**できること（申請に必要。LPで「バイテックが発行します」と書いている）

## 6. 学習機能（LPの「特長」「学習サイクル」で訴求しているもの）

| LPでの表現 | LMSで必要なもの | 現状 |
|---|---|---|
| オンボーディングで目的を登録 | 学ぶ目的・担当業務・AI経験・学習時間の質問 → 出発点を決める | 要確認 |
| 道のりを設計（マイルストーン） | 目的に合ったマイルストーン（職種別テンプレートあり） | あり |
| 期日を決めて進める（ロードマップ） | 達成日から逆算した期限設定・月ごとのロードマップ・予定と実績 | 要確認 |
| AIと積み上げて達成 | AIへの質問（LPでは「AIバディ」表記、LMSでは「AIチャットボット」）・実践課題・トレーニング | 一部あり |
| 特長01 最後まで続く仕組み | **チーム内ランキング**（同じチーム・部署のメンバー同士の学習時間ランキング）と**自動リマインド** | 無し（個人の週間ランキングのみ） |
| 特長02 自社のAIツールに合う講座 | 社内で使うAIに合わせて講座をカスタマイズ | 要確認 |
| 特長03 毎週点検で常に最新 | **講座を週1回点検・更新する仕組み** | 開発中 |
| 特長04 進捗・レポートを自動化 | 部署・個人ごとの受講状況の管理画面、**受講レポートの自動作成** | レポートは開発中 |

## 6-2. 研修管理者向けAI機能（LPの「AI機能」管理者タブで訴求）

LPには「順次追加」などの注記を付けていない＝**ローンチ時に全て実装済みが前提**。権限どおり、部署管理者には担当部署の分だけ見せる。

| 機能 | LPでの表現 | LMSで必要なもの |
|---|---|---|
| AI週次レポート | 受講者一人ひとりの学習を、AIが毎週レポート | 週1回、受講者ごとに「今週のサマリー／改善点／今後の伸びしろ」をAIで生成し管理者に届ける。全体KPI（受講者数・学習時間・修了本数） |
| AI受講アラート | 止まりそうな人を、AIが早めにお知らせ | ログイン間隔・進み具合の変化から学習停滞の予兆を検知して管理者に通知。本人に送る**声かけ文の案**をAIが作成 |
| AIスキルマップ | メンバーごとのAIスキルを、AIが見える化 | 学習の進み具合と実務トレーニングの結果から、部署の**メンバー一人ひとり**のスキル（文章作成・資料作成・データ分析など）をスコア化し、得意・苦手を表示。苦手なスキルに合う講座をメンバーごとに提案 |
| AIメンバー別マイルストーン | メンバーごとのマイルストーンを、AIが作成 | 部署のメンバー一人ひとりの担当業務・AI習熟度・社内で使うAIツールから、何をどの順番で学ぶかの**マイルストーン（ステップ・期日）をメンバーごとに**AIが作成。管理者が確認・承認すると各メンバーに配信 |

## 7. その他

- 無料トライアル：LPのフォーム（formrun・未設定）から申込み → Discordに通知。トライアル用アカウントの発行方法はLMS側で決める
- LPの画像（学習サイクル4枚・特長5枚）はLMS画面風に作ったイメージ。表示している機能（チーム内ランキング・リマインド・講座の更新履歴・部署別受講状況・ライセンス管理）が実装と食い違わないか確認する
